## Script + design understanding (read scripts/measure_finephrase_overlap.py + .sbatch + README)

- CLI: `measure_finephrase_overlap.py {tree,hash,reduce,selftest} --work DIR [--out PATH] [--shard N --nshards N] [--sample-mod 1] [--allow-partial] [--eduweb-configs data] ...`
- `hash` phase: reads `{work}/tree.json` (MUST already exist), builds a deterministic global sorted file list, takes files `i, i+n, i+2n, ...` for `--shard i --nshards n`, writes `{work}/hash/shard-{i:05d}.npz` (uint64 key arrays per group) + `.json` (stats/schema evidence). Idempotent: re-run skips if npz+json exist, `complete: true`, matching `n_files` and `sample_mod`. No S3 awareness at all -- pure local filesystem under `--work`. On Batch this means: stage tree.json into container at `--work`, run hash, then push the shard npz+json OUT to S3 ourselves.
- `reduce` phase: reads `{work}/tree.json` + ALL `{work}/hash/shard-*.{npz,json}` (needs every shard index 0..nshards-1 present, else FATAL unless `--allow-partial`, which we must NEVER pass). Writes `--out` JSON. Needs ALL shard files pulled back from S3 into one work dir first.
- HF auth: `hf_headers()` checks `HF_TOKEN`/`HUGGING_FACE_HUB_TOKEN` env, else reads `~/.cache/huggingface/token` if present, else anonymous. We will NOT set any token env var and the Batch container image should have no such cache file -- anonymous path only. Confirmed no credential file will be read as long as we don't stage one into the container.
- `--eduweb-configs` is a TREE-phase-only flag (baked into tree.json's `groups`); hash/reduce just consume whatever groups are in tree.json. Since tree.json is already built with `eduweb_configs: ["data"]`, we do NOT need to (and must not) pass --eduweb-configs again -- it's already locked into the artifact we're given.
