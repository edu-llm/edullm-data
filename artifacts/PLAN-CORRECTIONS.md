# Corrections to `DATASET-DESIGN-reservoir.md` found while executing Phase 0

2026-07-31. Every item below was verified by execution or a live API call, not inferred. Each names
what the plan says, what is actually true, and what it costs. Nothing here changes a *design
intent* — they are all cases where the plan's mechanism does not exist or does not work as
described.

**None of these required a decision beyond the plan's own logic**, so Phase 0 continued. They are
collected here because several touch decisions the plan lists as CLOSED, and the §9.1 hard-stop
report must not present a closed decision as sound when its mechanism is broken.

---

## 1. `_dedup/clusters.parquet` would be REJECTED by Gate A

**Plan says** (§1.3, the recommended option A for MinHash cluster IDs): write
`_dedup/clusters.parquet` "alongside the payload, as a **control file** outside the hash chain,"
with the stated trade-off "Backfillable, no schema change, **no Gate A risk**."

**Actually:** Gate A rejects it. Verified by execution against `validate.py`:

```
_is_control_key('_dedup/clusters.parquet')  -> False
_is_control_key('_licenses.parquet')        -> False
_is_control_key('README.md')                -> True
_is_control_key('_catalog/x.json')          -> True
```

The allowlist is closed and short:

```python
CONTROL_BASENAMES = {'README.md', '_REJECTED.json', '_SUCCESS', '_VALIDATED.json',
                     'dataset.json', 'manifest.json'}
CONTROL_PREFIXES  = {'_catalog/', 'dependents/'}
```

and `_is_control_key` anchors basenames to depth 0 (or depth 1 for a group's own
`manifest.json`) — deliberately, per its docstring, so `sneaky/README.md` cannot hide from the
exhaustiveness sweep. A `.parquet` at the dataset root matches nothing, so it is neither payload
(not in a group) nor control, and trips `unlisted-object-dataset-level` (`validate.py:626`).

**Cost: one line**, adding `_dedup/` and a licenses path to `CONTROL_PREFIXES` (plus a test and a
failing fixture, per `CONTRIBUTING.md`). Cheap — but it is a **code change to the shared validator
that must land before the first publish**, which the plan does not account for. It also affects
task B's `_licenses.parquet` identically.

**Do not work around it by hiding the file under `_catalog/`.** That prefix passes, but it is the
version resolver's namespace; putting unrelated artifacts there would corrupt discovery.

## 2. There is no "24-topic taxonomy"

**Plan says** (§1.2, §9.4): classify into "**Essential-Web's published 24-topic taxonomy**," and
"do not invent categories."

**Actually:** Essential-Web publishes the **Free Decimal Correspondence** with **12 main
categories**, whose **Level 1 has 10 values**. Verified verbatim on both cards. "24" is the
paper's *token count* — its title is "Essential-Web v1.0: **24T tokens** of organized web data."

And `EAI-Distill-0.5b` does not emit a topic at all; it emits **ten comma-separated fields** (FDC,
Bloom cognitive process, Bloom knowledge domain, document type v1 and v2, extraction artifacts,
missing content, reasoning depth, technical correctness, educational level).

**Resolution: FDC Level 1, 10 categories** — Essential-Web's own published scheme, so the plan's
"don't invent categories" intent is honoured exactly. Full reasoning, including why not Level 2/3
(too fine for a permanent path segment) and why not `document_type_v2` (classifies *format*, which
`source` already encodes): `artifacts/smoke/SUBSTRATE.md`.

**Consequence for the gate:** the ≥85% bar was set against a 24-class problem that never existed;
it is now a 10-class problem, chance 10%. 85% remains demanding. Flagged so the human deciding at
the hard stop knows the bar was not calibrated to the task actually being measured.

## 3. Judge B is unreachable; a proxy is used

**Plan says** (§9.4): judge B is `Qwen/Qwen2.5-32B-Instruct`, "the model D was distilled from."

**The teacher attribution is correct** — verified verbatim on the D card: "82B synthetic tokens
generated by **Qwen2.5-32B-Instruct (teacher model)**."

**But it cannot be called.** Probed live:

```
Qwen/Qwen2.5-32B-Instruct -> HTTP 400
  "not supported by any provider you have enabled"
```

Served only by `featherless-ai`, not enabled here. Self-hosting is out: the only GPU compute
environment is `g5.xlarge` (one A10G, 24 GB) and 32B needs ~64 GB in fp16.

**Resolution:** `Qwen/Qwen2.5-72B-Instruct` — same family, generation and tuning recipe, so its
errors should correlate with the teacher's, which is the only property judge B needs (it exists to
detect *inherited error*). Verified live on the router.

**It is a proxy and the report says so.** If the 72B sibling is a better classifier than the 32B
teacher, it sides with A more often and **understates** inherited error. The `J = agreement(A,B)`
ceiling is measured on the pair actually used, so the gate arithmetic stays sound.

## 4. `entry.labels` cannot carry a license either — and no join key exists

The plan already corrected itself on cluster IDs in `entry.labels` (§1.3). The same wall blocks
task B's per-document license: `_check_labels_match_path` requires `declared == expected` exactly.

Worse, and this is new: **the manifest's grain is one shard object**, so there is no per-document
key to join a license row to. A `(shard_path, doc_index)` key would work — EOS boundaries are
recoverable from a `.u32le.bin` via `(mmap == eos_token_id).nonzero()`, as §2.3 notes — **but the
tokenizer has to emit it at build time.** After tokenization the document→row mapping is gone.

**This is the one item in task B that must precede the first publish**, and it is genuinely
irreversible in the plan's sense. It belongs on §1's list.

## 5. `CLAUDE.md` is stale about the deployed wheel

**`CLAUDE.md` says** the live job defs "bootstrap `0.2.0` by exact filename."

**Actually** `edullm-validator:6` bootstraps **`edullm_data-0.5.1-py3-none-any.whl`**, and the
family was at revision **6**, not 2. Verified by `describe-job-definitions`. `HANDOFF.md:54` has
the current figure. No action needed for Phase 0 — recorded because the stale line would mislead
anyone re-registering a job def.

## 6. My own bug, for the record: anonymous API calls got rate-limited

Not a plan error. `recount.py` initially called datasets-server anonymously, and with 9 agents plus
a harvest running concurrently the shared anonymous quota was exhausted — every in-flight count
failed at once with HTTP 429, which looked like broken corpora. Fixed two ways: send the HF token as
a Bearer header, and give 429 exponential backoff to 120 s instead of a 3 s linear retry that could
never outlast the limit. Affected agents were told to re-run and to serialize.

Worth keeping in the record because the failure mode is **indistinguishable from a broken corpus**
in the artifact, and a future run at higher fan-out will hit it again.
